🔄 新增 handoff 按钮：把任务完整搬到新对话

docs/change-explainers/2026-08-31-ui-handoff-button.html · 对应代码包 packages/client/ui-handoff

📌 一句话结论：以前换对话要手动复制粘贴才能续接任务；现在输入框右侧多了一个 “交接”(Handoff) 按钮，点一下，AI 会自动生成任务交接包、开一个新对话把交接包放进去，然后把旧对话归档，全程不用复制粘贴。

🧩 生活类比

就像你把一份做了一半的工作交给同事：你先把“现在做到哪、目标是什么、下一步做什么”写在一张交接单上（handoff 技能生成交接包），然后把交接单放到同事的新工位（新会话直接输入），最后把你的旧工位收进档案柜（归档旧会话）。你不需要自己跑腿复印，按钮替你完成了整套流程。

🛤️ 人话链路（点步骤看细节）

1点击“交接”按钮
按钮在输入框右侧工具行，空闲会话才可点；生成中会变成“生成中”并禁用。
2AI 运行 handoff 技能
向当前会话发送以 /handoff 结尾的提示词，宿主识别该手势并注入技能说明，模型据此产出交接包。
3截获交接包
监听会话事件流，等这一轮结束，取最后一条助手消息的全文作为交接包（Markdown 原样保留）。
4新建会话并输入
在同一工作区创建并打开新会话，把交接包作为新会话的第一条用户消息直接发送。
5归档旧会话
交接包成功进入新会话后，旧会话通过现有归档能力收进归档列表并从侧栏隐藏。

💡 任何一步失败（比如没装 handoff 技能、模型没产出交接包），都不会归档旧会话，输入框会给出对应提示。

核心编排逻辑（src/client/handoff.ts） 
// 核心流程：查技能 → 订阅事件 → 发 /handoff → 等 turn/end → 提取最后一条助手文本
const fromSeq = lastSeqOf(deps.eventWindow(sessionId))
subscribeEvents(sessionId, () => {
  const extraction = extractHandoffPackage(eventWindow.entries, fromSeq)
  if (extraction.kind === 'pending') return
  if (extraction.text === '') reject(no-package)
  else resolve(extraction.text)
})
await deps.prompt(sessionId, promptText)   // 提示词以 /handoff 结尾
const packageText = await packagePromise    // 等的就是这一步的结果
const newId = await deps.createSession(workspaceOf(sessionId))
deps.openSession(newId)
await deps.prompt(newId, packageText)      // 交接包作为新会话第一条消息
await deps.archiveSession(sessionId)        // 最后才归档

🛡️ 没动什么 / 风险边界

🚫 没有改会话日志格式、Agent 循环或公共 API——交接包和触发提示词都是普通 user/message，模型可见内容依旧能从日志完整重建。

⚠️ 依赖 handoff 技能存在：技能不在技能目录时按钮会提示“未找到 handoff 技能”，不会乱发消息。

⚠️ 自动流程无预览：按你确认的默认行为，交接包直接作为新会话首条消息发出、旧会话自动归档，没有人工复查步骤（未来可加草稿预览）。
